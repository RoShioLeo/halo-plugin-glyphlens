# 字库与转换规则

## 转换规则

- 原创转换内核独立实现，不使用 CHAR 转换器或其汇总字库。前端复用维护者此前以 MIT 发布的页面与交互。
- 通用表处理与方向无关的字形，例如竖排标点；简体、繁体表分别补充方向关系。后台列表和导出只包含所选表，转换时才合并为最终索引。通用记录（含待确认关系）不再重复列入繁简表。
- 通用表作为基础，方向表的启用规则优先覆盖同一原字。方向规则停用后回退通用映射，通用映射也不可用时保留原字。后台停用行仍展示原映射，状态以绿、红、黄圆点分别表示启用、停用、待审。
- 批量操作随所选状态切换：启用项可停用、待审项可审核、停用项可启用；混合状态不可操作。审核需要逐项查看候选并明确确认，启用恢复停用前保存的规则和备注。
- 初始使用**默认转换**，取已收录候选中的首选；**多字候选**在正文标记需校对的位置，点开后显示合法候选并逐处选择。复制、下载输出选定正文，未校对处沿用首选；前端不再把候选括号拼进正文。
- 基础候选按使用等级排列：简体参考《通用规范汉字表》一级、二级、三级，繁体沿用附表中对应规范字的等级（多个对应取最高等级）。同等级保留原字优先，其余以码点稳定排序；这不是逐字词频排名。自定义修正沿用管理员保存的顺序，词典消歧优先于默认首选。
- `乾/干` 等有依据的兼用关系已录入，保留原字作为候选；来源冲突和未证实的补充候选单列核查。
- 查不到就保留原字和原始编码；替换只基于原文计算一次，不作连锁替换，不对全文做宽泛的 NFKC。
- 带变体选择符、组合附加符或连接符的多码点字形整体保留；字库未定义这些组合时，不转换其基字，词典消歧也不会跨过它们匹配。
- 词典只能在现有字形候选中消歧。词汇转换能力单独预留，当前未启用。


## 正式附表中繁简同形的异体字

正式附表直接收录的异体字，若只有一个规范对应，且目标字在正式附表、OpenCC 和 Unicode 中均没有其他繁体写法，可将已知简体对应同时用于繁体。只在繁体方向尚无启用规则、待审候选恰好相同、简体侧无额外候选冲突时生效。

本次归并 249 条（243 个原字及 6 个 Unicode 兼容字别名），直接放入通用表；不扩大参考来源的常用字范围，也不覆盖已有方向规则。

## 收录与优先级

目标是将非常用异体字归一到常用字，不追求将所有异体字替换为某个正字。

1. 保留原有来源的有效映射、候选及顺序。参考资料不能覆盖或追加到现有有效规则；与现有待审资料冲突时也不自动补入。
2. 常用范围：简体《通用规范汉字表》一级、二级字；繁体参考字典 A 类常用、B 类次常用字。三级、罕用目标不参与参考来源的自动补充。
3. 原字属于规范字、正式繁体对应或参考字典正字集合时，只作为参考；不自动新增异体归并。现有正式繁简规则继续生效。
4. 原字仅为异体、原始对应唯一、目标符合常用范围时，缺失方向直接补入并启用，不要求逐条确认。先检查所有原始对应是否唯一，再筛选常用目标，不能通过丢掉罕用目标伪造唯一关系。
5. 多目标、未编码关系不自动补入，也不塞入待审列表。原字和目标相同的关系不增加记录。
6. 人工保存的候选全部与参考资料吻合且目标符合上述常用范围时，自动保存为“基础补充”。通用补充须在简体、繁体两个方向都吻合；只吻合一个方向则保留为普通人工修正。
7. 基础补充与人工修正分层持久化，保留候选顺序、备注和操作记录。可停用；普通修正重置后恢复基础补充，不会把基础补充一起删掉。既有人工修正在再次保存时才做佐证判断，不在读取时悄悄改写。

参考数据不用于重新排列已有候选。简体对应优先采用正式附表，缺少时才用 OpenCC 通用字符表解释参考目标的简体写法；不引入地区专用 TWVariants 表。

### 数据快照

基础收录依据为《通用规范汉字表》8,105 个规范字、附表 2,574 条繁体对应和 1,023 条异体对应。Unicode 规范等价用于兼容字映射；OpenCC 仅使用通用 TS/ST 字符表，未被正式附表佐证的补充关系进入待审，不自动生效。

当前通用表 5,885 条，简体方向 6,612 条、繁体方向 8,586 条；合并后分别为 12,497、14,471 条。不保存仅将原字映射到自身的基础记录，未命中时保留原字；多候选中的合法原字仍保留。两方向排序或待审候选不同的记录分别保存在方向表中。

通用、简体、繁体表分别有 1,124、221、865 项原来源补充候选待审，已确定的候选继续生效。参考资料被排除的关系不加入待审队列。
