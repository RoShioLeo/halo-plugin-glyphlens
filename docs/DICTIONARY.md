# 字库与转换规则

## 单一字库

0.2.0 将原通用表与简体表合并为 `data/dictionary.json`，只处理繁体、异体字到常用简体的字形对应，以及竖排标点到横排标点。转繁体功能及其字库已移除。列表、新增、编辑、审核、导出、反馈和词典均不区分方向。

0.2.2 默认字库包含 **12,718 个原字、12,787 条候选对应**，其中 **69 个多候选原字，0 项待审**。默认数据以此前实际启用的简体映射为基础，加上维护者明确确认的关系；没有额外改动其他已启用映射。

维护者确认的 **225 项**候选及顺序保存在 [默认修正清单](../research/maintainer-decisions.json)。其中包含原有后台手工修正及后续 62 项审核结果，不附带账户、私人备注或修改历史。确认关系优先于自动来源排序，不会在重建时被覆盖。`䌷` 的候选为 `䌷／绸`；`硷` 只保留 `碱`。

本次不采纳 `么→幺`、`俱→具`、`像→象`、`哩→里`、`坏→坯` 补充；这五个原字保留原样，不再待审。调整后的顺序为 `彷→彷／仿`、`畫→画／划`、`箚→劄／札`；`麼` 仅保留 `么`。`乾→干／乾` 等现有人工顺序进入默认字库。

## 转换与校对

- 初始为“默认转换”。默认候选优先采用词典唯一命中的字形，未命中时取首个候选；手动选择始终优先。
- “多字候选”模式下，候选位置持续显示下划线，可直接点击进入该位置校对；也可点击右侧“开始校对”逐处检查。虚线表示待校对，实线表示已确认，两者均可点选修改。同字在不同位置可独立选择；结束校对或切换查看模式保留选择，修改原文后重新生成。
- 词典只推荐默认候选，不自动标记已校对。逐处选择或点击“确认剩余”后才标记已校对；“确认剩余”不改变当前显示的字，之后仍可逐处修改。
- 复制、下载输出当前正文，未校对处沿用当前默认候选。多字候选文件先展示结果，再手动开始校对；默认文件转换直接下载。
- 未收录的字保持原始编码。对原文只查表一次，不连锁替换，不对全文做 NFKC。
- 带变体选择符、组合附加符或连接符的多码点字形整体保留；词典也不跨过这些组合匹配。
- 词典只在现有候选中消歧，不翻译词汇。默认提供 9 个原字、18 组规则、75 个简体词条，可在后台编辑或停用。算法、收录范围和来源见 [词典说明](LEXICON.md)。

## 来源统计

生成程序按最终默认字库逐条计算每个来源采用的原字数和候选对应数，后台资料来源页读取 `data/sources.json`。README 保存同版本统计，不显示外部资料的原始规模。

每个“原字 → 候选字”计一条对应，包括多候选中的原字选项。同一原字的候选来自不同来源时，各来源原字数会重叠；每条对应只归入一个来源，全部对应数相加为 12,787。统计保留已启用来源的归属；人工确认的补充按实际参考依据归类，无资料依据的候选归入维护者补充。人工审核状态与资料来源分开统计。

## 收录与优先级

基础来源为《通用规范汉字表》8,105 个规范字及附表 2,574 条繁体、1,023 条异体对应，Unicode Unihan 和 OpenCC 通用字符关系。ST 字符表只用作辨别来源推断的依据，不编译为转繁体字库。

1. 现有来源的有效关系优先，补充参考不能覆盖或重排已有候选。
2. 非常用异体的原始对应唯一、目标为规范字一级或二级、且不存在已知来源冲突时，可由参考资料自动补入；多目标、未编码和罕用目标不自动激活。
3. 规范字、正式繁体对应及参考字典正字作为原字时，只补充参考，不以参考来源自动归并。
4. 未证实的补充关系不参与转换。待审候选仅允许规范简体字及原字，清除仅因旧通用分组而带入的转繁体提议。先保留来源冲突检查，再清理无效候选，避免清理操作意外激活新的参考映射。
5. 自动候选按规范字等级排列；同等级原字优先，再以码点稳定排序。人工确认的候选严格沿用保存顺序。
6. 管理员保存的候选全部获得补充参考佐证时，进入持久化基础补充层。其余作为普通修正；重置普通修正恢复默认映射或基础补充。

## 后台数据

统一字库使用 ConfigMap `lemonslice-glyphlens-dictionary`。启用、停用、待审以绿、红、黄圆点表示；停用后保留原字，列表仍展示停用前候选。

新增、编辑均填写原字和每行一个候选，支持字形或 `U+4E00`、`0x4E00`、`4E00`。候选按填写顺序保存，不生成反向关系。批量操作只允许状态一致的条目，审核须明确确认候选和顺序，写入受版本冲突保护。

0.2.0 按维护者要求重新安装，不导入旧方向字库、审核或修改历史。后续在新版中进行的管理操作正常留存记录。
