## 最新确认的范围

1. 目前只做单字字形、繁简及正异字转换，支持默认转换与多字候选。
2. 词典用于多候选消歧，仅能选择已收录候选；未来完整词汇转换另留能力，当前禁用。
3. 通用、简体、繁体三表分开维护，运行前合并为最终查询表。方向人工修正优先于通用人工修正，随后才是方向基础表、通用基础表。
4. 兼用字如乾/干，用户最后明确允许先将有依据的可转换关系录入。不要再按更早的要求将所有这类关系阻断。保留原字候选，来源矛盾和未证实的补充关系继续列核查。
5. 查不到就保留原字及原始编码，不能猜测、删字或对替换结果继续替换。
6. 用户明确要求竖排标点：︵︶→（），︻︼→【】，﹁﹂→「」，﹃﹄→『』，︽︾→《》，︿﹀→〈〉。已在通用表中。
7. 前端沿用现在的样式，但名称统一字镜/GlyphLens；博客工具菜单最终改成「私厨 / FRP / 字镜」。
8. 预留并实现反馈入口：单字、建议字形、说明入后台待核查，不直接改变字库，不自动上传文章全文。

## 线上迁移边界

- 当前旧插件 ID 为 `lemonslice-char`，新 ID 为 `lemonslice-glyphlens`。
- 旧自定义字库位于 Halo ConfigMap `lemonslice-char-v2s`、`lemonslice-char-v2t`。必须部署前重新读取，用户曾继续编辑，不要用研究快照覆盖实时数据。
- 新版三表自定义与历史统一保存在 `lemonslice-glyphlens-dictionaries`，由一个资源版本保护。
- 超级管理员 API 前缀 `/apis/console.api.glyphlens.lemonslice.cloud/v1alpha1`，`POST /migration/char` 读取两份旧资源并一次保存。接口可重复调用，不修改原资源。
- 先备份旧插件、字库及菜单；验证新插件和迁移结果后再停用/卸载旧插件，随后切换菜单及验证旧 URL 跳转。
- 菜单父项 `lemonslice-tools`，第三项当前 ID `lemonslice-char`。新名称应为字镜、地址 `/tools/glyphlens/`；私厨和 FRP 顺序保持。
- 不修改已有文章内容，不改动另一个已完成的 LensMD 插件。
- 凭证通过当前机器的授权方式取得。仓库没有保存任何登录信息，不要从提交历史寻找密钥。

## 本地继续

```bash
git clone https://github.com/RoShioLeo/halo-plugin-glyphlens.git
cd halo-plugin-glyphlens
node --test tests/*.test.mjs
./gradlew build --no-daemon --console=plain
```

Windows 使用 `gradlew.bat`。公开页面源码在 `web/`，控制台在 `ui/src/`，服务端在 `src/main/java/cloud/lemonslice/glyph/`，数据整理入口为 `scripts/prepare_catalog.py`。

本机 Node 24 的初步查表比较使用约 1.7 万关系、25 万字：分段数组约 26ms/29ms，字符串 Map 约 44ms/47ms；索引约 417KiB/方向。此数据不是跨设备承诺，需要用最终字库在浏览器重测。
