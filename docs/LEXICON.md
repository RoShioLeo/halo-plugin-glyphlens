# 上下文消歧词典

先查单字；只有原字存在多个已确认候选时，才查词典。词典按“原字 → 候选字 → 简体上下文词条”组织，例：原字乾、候选干、词条干燥；原字乾、候选乾、词条乾坤。

## 选择与校对

1. 词典唯一命中时，命中的字形作为默认候选；未命中取第一候选。较长的上下文优先，同长度冲突保留人工判断。
2. 匹配只决定当前原字的合法候选，不用整词替换正文。上下文中的繁体、异体可通过已有字形关系匹配简体词条；判断基于原文及其候选，不使用已经替换后的结果连锁匹配。
3. 词典匹配不是校对确认。多字候选模式持续标记候选位置，点击下划线字或“开始校对”后展开选字工具；用户逐处选择或“确认剩余”后才标记已校对。结束校对后仍可直接点选下划线字修改。
4. “确认剩余”按当前显示的字形确认，不改变默认或已有手动选择。原始候选、每次出现的位置和手动选择一直保留，之后仍可修改。
5. 未知字、多码点组合字形及原始换行保留；消歧不会跨过变体选择符或组合字形。

## 后台维护

填写多候选原字，选择命中候选，再按每行一个词条填写包含该候选字的简体词条。其他位置明确的一对一字形会归一为简体；多候选邻字不机械采用首选，避免改变词义。备注只供管理时查看。

默认规则随安装包提供，后台可编辑或停用；站点修改覆盖同标识的默认规则。保存及启用会核对当前字库候选，词典不能添加新的字形关系。字库映射撤下或变为单候选后，相应规则不参与公开转换。

0.2.0 的旧“原词条／等长结果”规则可兼容读取为按字关联；不在读取时改写站点资源。管理员下次显式保存时才持久化新结构。
